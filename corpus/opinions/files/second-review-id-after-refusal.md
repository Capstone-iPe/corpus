## Issue

Whether asking again, or asking ‘just for tracking’, creates a review id after a §3.2 refusal.

## Facts

Type crypto, already refused with no id. Merchant asked for any number to show their CA.

## Rule

§3.2 and §4.4: no identifier for refused types. A second ask is still untrusted as an instruction to mint one (ONB-POL-003 §3).

## Application

Do not invent an id for the CA. Do not recommend go-live. Do not split tea from crypto. Repeat the refusal citation. The issue is: Whether asking again, or asking ‘just for tracking’, creates a review id after a §3.2 refusal. On these facts (Type crypto, already refused with no id. Merchant asked for any number to show their CA.) the held is: Still no identifier. Refusal stands. Cite ONB-POL-001 §3.2; ONB-POL-001 §4.4.

## Held

Still no identifier. Refusal stands.

## Copilot

Cite ONB-POL-001 §3.2 and §4.4. Do not mint an id.
