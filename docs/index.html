Why we ship 800 / 120 + hybrid

From eval/retrieval.md: 24 fixed why/cite questions, gold document_ids, scored with hit@4 / hit@8 against a local index (Capstone bge-small-en-v1.5). Shop gold in analysis is not indexed here.

Chunk size bake-off

Hybrid hit@4 on the same question set:

0.875

0.958

Keep 800/120. Smaller chunks diluted hit@4. Larger chunks matched hit rates but did not beat 800/120 enough to justify rebuilding the deploy index. Same size family as Assignment 05. hit@8 was 1.0 for both 800 and 1200.

Search (runtime)

What happens on each query

The FastAPI service loads chunks.jsonl + vectors.npy once, rebuilds keyword postings in memory, then serves hybrid search.

01

Embed the query

Same Capstone embeddings API + L2-normalize. Only this one string is embedded per request.

02

Dense rank

vectors @ query → cosine scores → argsort. Closest chunks first.

03

Keyword rank

Token overlap against an inverted index. Exact ids and rare phrases.

04

Hybrid merge

RRF fuse + folder tier bonus → one chunk per document → return passages.

Copilot calls POST /v1/search with Bearer CORPUS_API_KEY. ONB still owns fields, files, and the verdict — this service only retrieves citations.
