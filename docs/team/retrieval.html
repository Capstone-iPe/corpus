Team · modes

Dense, keyword, hybrid, MiniLM rerank

Four ways we ranked the same 800/120 index on 24 fixed why/cite questions.

Dense

Meaning search with embeddings. Query → vector; compare to stored chunk vectors with cosine similarity (dot product after L2-normalize). Good at paraphrase; weaker on rare exact tokens.

hit@4 = 0.792

Keyword

Word-overlap search. Tokenize the query; look up each term in an inverted index (term → chunk ids); score by hit count. Good at ids/phrases; weak when wording differs.

hit@4 = 0.583

Hybrid

Both, then merge. Dense order + keyword order fused with RRF, folder tier bonus, one chunk per document. Fixes each method’s misses.

hit@4 = 0.958 · ships on Render

Hybrid + MiniLM rerank

Second-stage cross-encoder (ms-marco-MiniLM-L-6-v2) rescores the hybrid pool as (query, text) pairs. On this set it hurt hit@4; needs torch — local probe only.

hit@4 = 0.833 · not shipped

Team · metrics

hit@k and mean recall@k

Each question has a gold list of document_ids. Search returns ranked unique documents.

hit@k

Binary per question: is at least one gold id in the top k? Yes → 1, else 0. Average over 24 questions.

Capstone primary: hit@4 and hit@8 — “did the right doc land in the shortlist?”

mean recall@k

Graded: for each question, |retrieved ∩ gold| / |gold| at cutoff k, then average.

Rewards recovering more of the gold set, not just one hit.

Example: gold = {POL-001, ANX-001}. Top‑4 includes both → hit@4 = 1 and recall@4 = 1.0 for that question. Only POL-001 → still hit@4 = 1, but recall@4 = 0.5.

Team · chunking

Why 800 / 120 (and not 1200)

Same hybrid mode; only chunk size changed.

400 / 60 2667 chunks
0.875
800 / 120 1446 chunks
0.958
1200 / 180 1063 chunks
0.958

400 diluted hit@4. 1200 tied hit@4/@8 (mean recall@4 only +0.007) — not enough to force a full deploy re-embed. Kept 800/120 (Assignment 05 size family).

02

vectors @ query → cosine → argsort.
